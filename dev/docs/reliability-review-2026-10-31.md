## 目标与实施选择

围绕用户提出的四项要求：模板/要求识别准确、写入确实生效、审查结果可信、项目职责清楚。
保留现有 Python / python-docx / OOXML 实现与唯一 registry 写入路径；以最小 DOCX
反例驱动修复。不引入另一个解析器、写入器或预设默认值来掩盖无法识别的要求。

选择原架构内修复，而非整体重写或仅改提示词：已确认问题位于规则目标、OOXML 继承、
属性优先级和验收覆盖，重写会扩大回归面，提示词也无法修正错误的有效值读取。

## 实施计划与边界

- [x] 识别：保留中英文摘要/关键词的语言约束；测试无语言范围、显式语言和双语文档迁移。
- [x] 有效样式：共用实际默认段落样式解析；测试有/无 Normal、自定义默认样式、样例提取、audit/apply/verify。
- [x] 样式写入：按继承值计算粗体/斜体 toggle；测试基础值与目标值的四种组合。
- [x] 列表：消除毫米与字符缩进冲突；验收继承编号和每个显式缩进参数。
- [x] 表格：处理全部实际单元格边框，独立读取全部边界；检验恢复原边框及未请求属性保护。
- [x] 审查：只读模板 audit 输出 coverage/limitations/compliance，不能把部分符合报告为完整通过。
- [x] 结构：修正能力测试路径与文档入口，把历史改造材料移出运行时参考；保留兼容 API。
- [x] 验证：定向回归先红后绿，最终全套 unittest、项目校验、smoke、修改范围静态检查；独立复核 diff。

不删除用户已有 `.agents/`、`output/`、`.tmp/` 或其他本地材料；不推送远端。
没有真实页面渲染及逐页检查时，只声明代码/结构层验证，不声明 Word/WPS/LibreOffice 视觉一致。

## 后续优化优先级

1. **建立可版本化的脱敏模板评测集。** 当前 Git 跟踪的是程序化回归，没有可直接复跑的真实学校模板基准。
   每例保存原要求、预期区域/语言/属性、期望未决项和禁止改动的对象。分别统计规则识别准确率、作用域误命中率、未决项漏报率、执行生效率和错误通过率，不能用测试数量代替准确率。
2. **逐项建立读写与验收覆盖矩阵。** 为每个 capability 列成功、无变化、继承、冲突、混合格式、异常写入和保留性案例。
   增加“删目标、漏写一个参数、写错到相邻对象”的失效注入；这类测试比单纯用同一读取器往返更能揭示误报。
3. **固定渲染环境做差异回归。** 针对多节、目录刷新、跨页表格、合并单元格、页眉页脚建立 Word/WPS/LibreOffice 的小型样例集。
   保存实际渲染器版本和字体；未跑的组合明确标记未验证。
4. **按职责逐步拆大文件。** `structures.py` 同时承载表格、目录、页码、引用和编号，`verification.py` 混合状态读取、比对与包保护，`profiles.py` 混合提取与绑定。
   在覆盖矩阵补齐后分批提取独立模块，保留既有导出/CLI兼容；避免一次迁移整个 `scripts/` 引发导入路径混乱。
5. **为冻结兼容数据设退出路径，并补持续集成。** 先记录旧 spec/API 的使用者和行为对照，再决定是否合并数据；新增功能只走模板入口。
   把当前可复现的校验、unittest、smoke加入真实CI工作流后再展示CI徽章；风格统一单独提交，便于审查。
