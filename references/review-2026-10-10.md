Add synthetic DOCX cases with footnotes, OMML equations, nested/merged tables, section-linked headers, content controls and REF/TOC fields. Keep conversion separate from this project's formatting core, then hand the resulting DOCX to the same inspect/audit/verify gates.
4. **Cross-renderer fixtures.** `thesis-docx` highlights style overrides, page/section drift and stale REF results. Test representative official templates in the actual target Word/WPS/LibreOffice environment, compare every rendered page and report renderer-specific differences rather than claiming a generic pass.

## Thesis generation trial follow-up

The later user-supplied thesis and Markdown retrospective were inspected read-only.
The user explicitly requested skill repairs, not changes to the paper. The
retrospective's explanations and reported speedup were treated as hypotheses,
not as validated implementation requirements.

| Finding | Verified evidence | Repair |
|---|---|---|
| Chapter-description prose was inferred as Heading 1. | Normal paragraphs beginning “第一章：绪论。介绍…” matched the chapter prefix. Changing their wording only hid the defect. | Use conservative shared text inference; preserve explicit Heading styles, reject sentence/colon descriptions, decimal values, list styles and TOC lines. Numbering uses the same inferred level. |
| The installed batching patch silently dropped requested role rules. | Its diff removed `merged.update(tokens)` together with the old per-paragraph loop; whole-document overrides no longer entered direct operations. | Retain token merging and group identical registered paragraph actions/parameters; verify each target independently, including direct overrides and module defaults. |
| Zero opposite indent suppressed nonzero first-line indentation. | WPS Word-compatible COM read both the old XML and the trial's dual-written 480-twips XML as 0pt when `hanging="0"`/`hangingChars="0"` remained. Character-only XML without opposite attributes read correctly. | Remove opposite attributes. Preserve character units and read the actual signed first-line/hanging offset; clearing an inherited opposite indent must execute rather than become a false no-op. |
| Cover metadata could receive body rules. | The object index started with no cover module even when the shared span detector identified front matter before declaration/chapters. | Classify that front matter as cover; keep body-only documents eligible for body formatting. Explicit module rules still apply. |
| The retrospective attributed a preservation failure to overlapping blank-paragraph modules. | Consecutive empty paragraphs and page-break runs passed the synthetic preservation regression; the original failing plan was not supplied. | Keep the preservation gate and legitimate blank paragraphs. Do not claim this root cause has been reproduced. |

New regression fixtures cover chapter descriptions through native numbering and
TOC generation, explicit heading precedence, retained batch parameters, blank
paragraphs/page breaks, cover metadata and body-only inputs, contradictory indent
XML, multiple font sizes, physical indents and clearing inherited opposite
indents. Fixtures and diagnostics are created in the OS temporary directory.

A 176-paragraph synthetic thesis using the full preset retained 1,640 per-target

The draft-authoring guidance now separates research evidence from formatting,

formatting in the user's thesis was changed.

Final validation: all 60 Python tests passed, including 7 new thesis regressions;
the DOCX smoke test, project validation (52 required files), skill validator and

## Heading color follow-up — 2026-10-11

The stock python-docx package gives Heading 1–3 accent1 theme colors; its Title
uses text2 plus theme shading. The user's theme-inheritance explanation was
correct in principle, but Title is not always accent1 and the actual RGB depends
on the installed document theme. The thesis preset omitted explicit colors.

The preset now requests `000000` for title and H1–H3 text. Optional `title` tokens
use the registered writers on Title/Subtitle paragraphs and their styles; module
headings without an explicit level receive the requested H1 color. Full presets
override direct run colors as well as inherited styles. Partial specifications
without color and explicitly colored template specifications retain their intent.

The color reader now resolves theme RGB/system colors and shade/tint before
checking a requested RGB. Previously a cached black RGB with accent1 could cause
the writer to skip a visibly blue run. The existing color writer removes theme
attributes when setting an explicit color. If a theme cannot be resolved, the
reader reports an unresolved theme instead of falsely accepting cached black.

Regression coverage includes stock styles, direct accent overrides with cached
black, module titles, custom title/heading colors and preserving theme attributes
when color was not requested. Local WPS COM read six generated-core fixture
headings (Title, Subtitle, abstract and H1–H3) as explicit black (Font.Color = 0).
No user thesis was modified. The optional title tokens extend the existing
specification additively and use the same planner, registry and verification.
