# 模板驱动重构方案与主仓库接入

日期：2026-10-29。主仓库：`D:/project/word-format-master`。

## 基础版本与接入方式

本次在主仓库已有提交 `df15e23`（preserve template formatting and validate TOC results）上接入模板重构。早期实现在 C 盘的安装副本中完成，未直接修改主仓库，也不能把该副本视为主仓库最新版本。

接入使用“重构前副本 / 主仓库 / 重构后副本”三方比较，只迁移重构增量。主仓库已有的封面字段识别、双语摘要、关键词标签与内容分开处理、规范文种范围、段落行单位、目录内容校验与正文首页页码控制应保留。主仓库的 LICENSE.txt、发布目录和 `_dev/` 开发布局继续沿用。

## 要解决的问题

现有生成脚本能产出外观统一的新稿，但格式参数与执行逻辑混在一起。迁移现成论文时，共享样式、默认字体、正文固定行距和手工标题序号容易影响样例没有要求修改的内容。仅检查已经执行的操作，也无法说明样例中的全部要求已经落实。

改造后，新稿先生成内容初稿，随后与现有论文使用同一套模板、计划、执行和验收流程。格式任务保留正文、数据、图片、公式和参考文献事实，不通过重建全文完成。

## 分层设计

| 层次 | 职责 | 输入与输出 |
| --- | --- | --- |
| 证据提取 | 读取样例和格式要求的直接格式、继承样式、页面、编号及复杂对象 | 原始材料 → profile |
| 模板编译 | 合并来源、记录冲突和未支持属性、保存来源指纹 | profiles 与决策 → 独立 template |
| 语义与绑定 | 区分章标题、模块标题、正文、文献条目、封面字段和图文对象 | template 与原稿 → 明确目标与覆盖账本 |
| 计划与执行 | 通过注册能力修改指定属性；执行前校验来源和计划完整性 | 计划 → 新 DOCX 与执行报告 |
| 独立验收 | 回读格式，核对对象保护、规则覆盖和视觉证据 | 输出与证据 → execution / compliance |

字体、字号、间距、纸张、边距、章节编号外观、封面布局都属于模板数据。代码只实现 Word 协议和文档语义，如标题层级、大纲级别、原生编号、目录不能收录自身，以及 `numId=0` 表示取消编号。

参考文献标题和文献条目应分别处理。GB/T 7714 的书目规则不代表所有学校的文献字体和悬挂缩进都一样，这些外观不能写成全局默认值。

## 模板选择契约

1. 用户明确选择内置模板时，加载 `templates/builtin/<id>/template.json`。内置三套模板彼此独立，封面布局另放 `cover.json`。
2. 用户给出样例、详细要求或两者时，先提取 profile，再编译用户模板；不继承内置模板填补缺失项。
3. 未说明的属性保留原值。冲突保留双方证据，不能按加载顺序覆盖。
4. AI 先根据已有材料处理能够确定的映射、冲突和适用范围；仅在材料不足且影响结果时向用户提问。
5. 无法自动迁移的复杂格式进入问题清单和覆盖账本，不能用“全部通过”掩盖未支持范围。

## 模板合同

模板包含 `schema_version`、`id`、`version`、`origin`、`sources`、`rules`、`evidence`、`issues`、`decisions` 与 `limitations`。

每条可执行规则必须有注册操作、目标选择器、参数和来源依据。来源记录绝对路径及 SHA-256；证据快照保留样式 XML、页面、编号和有效属性。修改来源、模板或目标原稿后必须重新规划。

规则不能找到目标、多节关系未映射、低置信度证据未经解释时，输出可审查的问题，不执行写入。样例迁移还需要核对目标段落覆盖，未覆盖内容必须有明确保留理由。

## 标题、对象与兼容

- 正文章标题使用 Heading N 样式、大纲级别和 Word 多级编号；“第一章”“第二章”来自 numbering.xml，不继续手工写入段落文本。
- 摘要、参考文献、致谢等模块标题使用独立标题样式，避免误接章编号。目录标题排除自身索引。
- 图片、公式及混合对象不作为普通正文套固定行距。复杂容器保留并明确记录支持边界。
- 保留主仓库已有封面和双语摘要身份，不能用新增通用语义覆盖它们；各级章标题提取仍需保留层级，不能合并为一个样式组。
- 关键词继续接受主仓库的 `label` / `value` 分段，兼容重构接口的 `content` 别名。
- 目录兼容原有 `title_style`，新模板使用 `title_format`、`field_format`、`break_format`；外观只取显式数据。
- 旧 spec 和 `assets/presets.json` 保持兼容，新模板不从旧接口隐式取值。

## 实施与验证

1. 核对主仓库工作区和已有修复，按文件三方合并。
2. 接入 `templates.py`、`numbering.py` 与语义扩展，新增独立内置模板和封面数据。
3. 为 CLI 增加模板列表、编译、校验、规划与只读检查入口；新稿和现成论文使用相同入口。
4. 保留 `_dev/tests/` 现有回归，补充模板与主仓库修复的组合测试；正式代码及新增测试使用 Git 提交。
5. 运行全量测试、项目校验和 smoke test，检查真实案例图片与内容保护。结构验收不能替代逐页视觉验收。
6. 从 `df15e23` 创建独立重构分支提交，保留原有 Git 历史与远程设置。

验收分别报告已执行操作的 `execution_status` 和整体覆盖的 `compliance.status`。无视觉证据时整体为 pending，保留未支持范围或跳过规则时为 partial。只有覆盖完整、格式正确且视觉验收通过，才报告整体 passed。

复杂文本框、脚注尾注、特殊编号几何和图像中的格式要求仍需进一步扩展；记录提取证据不等于已经完整自动迁移这些内容。
